# Music Data V2 Integration Contract (2.1.0)

The data package is deliberately independent of the application. The canonical tables live in `tables/`, original spreadsheets in `raw/`, and browser-friendly materialized views in `runtime/`. The app must load `runtime/manifest.json` first, then use only paths advertised in `manifest.api`; it must not assume the directory holds the newest raw workbook unless all derived data have been rebuilt.

Deploy as sibling folders `app/` and `music_data_v2/` under one web root and serve with HTTP (for example `python -m http.server 8000` from the root). File-system `file://` loading is not supported. The browser reads `../music_data_v2/runtime/manifest.json`. For separate origins, configure CORS. Data can be updated without changing the app if the contract version remains compatible.

`observations` has one row per chart placement and foreign keys `source_id`, `source_item_id`, `performance_id`. The platform item groups the same platform identifier; a performance groups identifiers conservatively. `performance_source_links` records the mapping basis. `entities` distinguishes persons, ensembles, organizational projects and unknowns. Source credit order remains in `source_item_credits`. Work IDs are provisional one-to-one placeholders, *not* verified composition identities. All researcher decision tables are currently empty and not automatically applied by `scripts/build.py`.

`runtime/periods.json` summarizes valid observations, per reporting week and source; top-20 share is computed separately **within** each source and measures ranking-list behavior, not population-wide listening. `runtime/weeks/YYYY-MM-DD.json` has the detailed observed *and* suspect source rows, positional data with a `columns` array, and a `data_status` flag. Spotify dates are mapped to Thursday-ending calendar weeks; YouTube weekly dates are not changed. Weekly periods with no observed records are missing, never zero. Do not add Spotify streams to YouTube views.

The 40 repeated YouTube snapshots dated January 5–October 5, 2023 are `suspect_repeated_snapshot`, quarantined from summary analytics. The first nonquarantined end date is October 12, 2023, which itself straddles October 7. Language/genre classification is unverified when blank. Source-furnished creator genres are not validated per-track genres. Event date descriptions require verification.

See `docs/schema.json` (all columns, PK/FK), `docs/DATA_DICTIONARY.md`, `docs/MODEL_DETAILS.md`, `docs/qa_report.json`, `docs/checksums.json` (checksums), `docs/validation_report.json` and the Hebrew contract for detailed methods and data limits. Run `python scripts/validate.py` before publication. On updating raw XLSX, **rebuild all CSV, QA and runtime layers together (run `python scripts/build_runtime.py` after the CSV rebuild)** and review identity migrations; replacing raw files alone is not a refresh.

**Release provenance:** This release uses the previously validated internally consistent V2 processed snapshot. There are later modified Google Drive workbooks; a full rebuild from them was attempted but not completed in this run. This package intentionally does not mix those newer raw files with outdated processed tables.
