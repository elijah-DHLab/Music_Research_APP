# חוזה האינטגרציה של חבילת הנתונים V2 (2.1.0)

## מטרת החבילה
חבילת נתונים נפרדת מהאפליקציה. היא מכילה את כל קובצי המקור של Spotify היומי, YouTube Tracks השבועי, YouTube Videos השבועי וקטלוג היצירות/היוצרים על שני הגיליונות שלו; טבלאות CSV מעובדות; נתוני תצוגה מחולקים לפי שבוע; סכמת קשרים, דוחות בקרה וכלי בנייה מחדש. האפליקציה לא חייבת להכיר את פורמט XLSX, אלא רק את `runtime/manifest.json` ואת ממשקי JSON שהוא מציין.

## מיקום תיקיות ופרסום

```
project-root/
  app/                     ← האפליקציה בלבד
    index.html
    app.js
    styles.css
  music_data_v2/           ← חבילת הנתונים, בנפרד
    runtime/manifest.json
    runtime/periods.json
    runtime/weeks/2023-10-12.json
    tables/observations.csv
    raw/*.xlsx
```

להפעלה מקומית מתוך `project-root`, הריצו `python -m http.server 8000` ופתחו `http://localhost:8000/app/`. אין להסתמך על פתיחה ב־`file://` מפני שה־Fetch API חסום בחלק מהדפדפנים. ב־GitHub Pages יש לשמור את שתי התיקיות תחת אותו בסיס נתיב. לשרתים נפרדים צריך CORS.

האפליקציה קוראת `../music_data_v2/runtime/manifest.json` ובונה ממנו את כתובות הנתונים. אין לשנות שמות קבצים בלא עדכון המניפסט. ערכים ב־`runtime/weeks/*.json` הם מערכי רשומות; סדר העמודות מפורש בשדה `columns` **בכל קובץ**.

## טבלאות הקשר המרכזיות

1. `observations`: טבלת תצפיות מקור; `observation_id` ייחודי; כל שורה מצביעה על `source_id`, `source_item_id`, `performance_id`.
2. `performances`: טבלת זהויות ביצוע **זמנית**; `performance_id` מזהה הביצוע, לא יצירה מוסכמת סופית.
3. `source_items`: מזהים משויכים לפלטפורמות; `source_item_id` יכול לשמש את שתי סדרות YouTube במקביל, אך תצפיות Tracks ו־Videos אינן מתאחדות.
4. `performance_source_links`: בסיס האיחוד ומצב בדיקתו. זהויות מבוססות כותרת + קבוצת מבצעים מלאה + גרסה הן **הצעות זמניות**, לא זיהוי מאושר.
5. `entities`, `performance_entities`, `source_item_credits`: הפרדת מבצעים, הרכבים וגופים. שימור סדר הקרדיטים המקורי. ״פסטיגל״ ודומים לו נחשבים גופים/פרויקטים *טעוני בדיקה*, לא אדם מבצע.
6. `works_provisional`, `performance_work_links`: שכבת יצירות זמנית אחד־לאחד עם ביצוע, בלי איחוד קאברים.
7. `coverage_observed`, `coverage_gaps`, `coverage_suspect`: שכבת כיסוי וחריגים; אפס הופעות ברשימת Top-N ≠ אפס האזנות, והיעדר מדידה ≠ אפס.
8. `identity_decisions`, `entity_decisions`, `metadata_corrections`: **טבלאות תבנית ריקות** להכרעות עתידיות; המערכת הנוכחית אינה מחילה אותן אוטומטית.
9. `quality_issues`, `candidate_merges_review`: תור סקירה; אינן הוכחה לכשל בכל רשומה.

כל עמודות הטבלאות, מפתחות ראשיים/זרים ואימות שמות מתועדים במכונה ב־`docs/schema.json` ובשפה טבעית ב־`docs/DATA_DICTIONARY.md` וב־`docs/MODEL_DETAILS.md`.

## ממשק האפליקציה (`runtime`)

| נתיב | תוכן | כוונת שימוש |
|---|---|---|
| `manifest.json` | גרסת סכמה, מדיניות נתונים וכתובות API סטטי | נדרש ראשון |
| `periods.json` | מדדים מקובצים לפי שבוע ומקור | ציר זמן, ללא טעינת מאות אלפי שורות |
| `weeks/YYYY-MM-DD.json` | כל תצפיות השבוע — גם חשודות; שדה `data_status` בכל שורה | פירוט שירים והורדת נתוני נקודה |
| `performances.json` | זהויות, סטטוס וקרדיטים לאימות | רשימת ביצועים |
| `entities.json` | אנשים, הרכבים, גופים/פרויקטים | סינון וישויות |
| `sources.json` | יחידות מדידה ורזולוציה | הצגת צירים והסברים |
| `coverage.json` | סטטוס כיסוי לכל תאריך מדידה במקור | רווחים בגרפים |
| `issues.json` | תקלות המזוהות בנתונים | בקרת איכות |
| `events.json` | אירועים לעיון, עם מצב אימות | שכבת אירועים |

`periods.json` מכיל לכל מקור/שבוע: `observations` = מספר תצפיות תקינות, `source_periods` = מספר תאריכי דיווח תקינים, `mean_chart_positions` = תצפיות חלקי תקופות דיווח, `sum_source_measure` = סכום כמויות באותו מקור בלבד, `top20_source_measure` וסך חלקם היחסי `top20_share_percent`, ו־`unique_performances`. אין לקשור סכום streams של Spotify לסכום views של YouTube.

Spotify היומי נקבץ למקטעים שבועיים המסתיימים ביום חמישי; שבוע חלקי יכלול פחות משבעה ימי מדידה. YouTube נשאר שבועי לפי תאריך סוף השבוע שנמסר. אין לפרש ממוצע נתח ב־Top-20 כמדד מספר האזנות במדינה כולה.

## מדיניות אמינות: חובת הצגה בכל תצוגה

- ברירת המחדל משתמשת **רק** בתצפיות שבהן `data_status === 'observed'`.
- `suspect_repeated_snapshot` נשמר במקור, אך אינו נכנס לאגרגציות, לגרפים, לממוצעים או לבדיקות שינוי.
- בשני מקורות YouTube מסומנים 40 שבועות משוכפלים (תאריכי סוף שבוע 2023-01-05 עד 2023-10-05; 7,960 שורות מקור). לכן *אין* סדרת YouTube מאומתת לפני 7 באוקטובר 2023. השבוע הראשון לאחר ההסגר (סוף שבוע 2023-10-12) חוצה את 7 באוקטובר, ואין להגדירו כשבוע 'אחרי' נקי.
- שבוע ללא רשומות תקינות אינו נקודת אפס ואסור לצייר קו לגובה 0 עבורו.
- מדידה מסוג `views` ו־`streams` לעולם אינן מצטרפות ביחידות מוחלטות. אפשר להשוות נתחים בתוך כל מקור, בציון יחידות/חלונות הזמן.
- `language_verified`, `genre_verified` ריקים עד אימות; אין להמיר כתב בכותרת ל״שפת שיר מאומתת״.

## בדיקה ותחזוקה

הריצו `python scripts/validate.py` לבדיקת טבלאות ליבה. `docs/checksums.json` מכיל SHA256 וגודל לכל קובץ בעת בניית מהדורת המסירה. לקבלת מהדורה חדשה יש לייצא קובצי XLSX חדשים, לבנות מחדש את הטבלאות, לבדוק זהויות ושינויי מזהים, להריץ `python scripts/build_runtime.py` כדי לייצר מחדש את נתוני runtime ולעדכן מניפסט. **אין להחליף XLSX בלבד** בתוך חבילה ישנה בלי לבנות מחדש גם את ה־CSV וה־runtime.

גרסה זו היא צילום עקבי של טבלאות V2 שעברו עיבוד קודם. קובצי Google Drive עודכנו שוב אחרי יצירתו; הניסיון לבנותם מחדש לא הושלם במעבר הנוכחי. לכן מהדורה זו אינה מתחזה להיות העיבוד האחרון של השינויים האחרונים ב־Drive. לא ניתן לטעון שהקבצים החדשים הוטמעו בלי בנייה ואימות מלאים.
